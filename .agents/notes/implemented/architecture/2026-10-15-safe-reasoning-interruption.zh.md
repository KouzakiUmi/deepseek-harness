# Agent Note: 推理策略在有界恢复前提交安全输出

Status: implemented

[English](2026-10-15-safe-reasoning-interruption.md) | 中文

## Problem

模型可能先输出很长的精确重复推理循环，随后才真正请求工具。首次重复短语时就取消会丢弃可恢复的工作；只过滤流式增量，又会让权威的完整块恢复被删除的文本。为提供方重放另存一份原始响应，会保留同样不需要的载荷，并可能再次发送给模型。

## Decision

适配器在与分派相同的 prepared snapshot 上声明推理编辑能力。未知和不透明路由不被编辑。pi-ai 显式的明文 Chat Completions 模式拒绝不透明元数据，为普通工具响应保留明文推理字段选择标记，并将仅含推理的历史投影为包含精确保留字节的 assistant 正文。direct Messages 签名仍然不透明。协议或提供方名称本身不构成编辑能力。

循环在分派前选择一个调用局部的输出策略。只有已接纳分片进入持久累计、规范组装和实时发布。推理闭合指令使用已接纳文本，而非提供方的完整块。插件保留有界原始／已接纳后缀与未决片段，不再存储另一份完整响应。精确副本抑制与延后中断采用独立预算；工具参数增量不构成执行授权。具有身份的完整工具块会保护正常结算，同时继续过滤推理。

本地策略停止拥有派生的调用信号，而非轮次信号。循环先取消调用并关闭迭代器，再授权恢复。清理失败仍然是错误；父级、用户和释放取消优先。普通中间件异常与提供方失败不进入本地策略恢复。策略停止绕开普通请求错误重试，包括 always 模式。已卸载策略可以完成已经捕获的过滤／停止，但不能授权下一次调用。

`assistant/message.interrupted: true` 表示尚未完成的安全正文／推理前缀，不表示取消者身份或最终轮次结果。嵌入式流记录策略失败，不伪造 usage、成功 finish、重放签名或工具结果。保留消息中没有未分派工具。带来源归属的续跑提示会在下一次请求之前作为普通持久 `user/message` 写入。有限的每轮预算让恢复保留在原有 activity 与原生子代理 activation 内，先于 error／idle 或子代理结算。

中断在其结算之前就可见。循环在策略结束调用的当下、提供方清理之前发布策略的真实失败帧，因为清理可能按传输层的决定长时间挂起；持久流与中断结算随后承载同一份事实，读取方既不会看到伪造的成功，也不会看到被复活的调用。需要保留读者已见内容的展示层，会把每个被取代的中断前缀留在继续它的那次尝试旁边，并展示续跑来源记录的续跑序号与 Turn 上限；在该续跑提示到达的当下，该 Step 回到运行中展示，而不是把这次截断呈现为停止。当记录的 Step、序号或上限缺失时，这些读取方保持原有的持久展示。

本决策部分替代[取消前缀定稿](2026-08-10-cancelled-stream-prefix-finalize.zh.md)中仅限用户取消的限制。该决策的取消顺序、工具省略与普通提供方失败行为继续有效。[嵌入式流决策](2026-09-01-v2-embedded-assistant-streams.zh.md)仍然负责紧凑流存储；所存流是已接纳输出，不包含隐藏的原始副本。

同一策略还会在某次初始窗口观察同时包含反复句子与重复使用字符后暂存输出：观察回落或出现屏障时原样释放，重复持续则结束调用。观察窗口向配置上限逐步扩展，该上限约束保留与观察，而不是必须等待的条件；到达上限时策略按当前证据决定——重复仍在持续则取消，已经回落则释放，而完整协议工具块之后仍可暂存但不取消。复现的句子还须具备实际字符质量，因此反复出现的口头填充词无法让“句子不断引入新标识符、计数器或结论”的进展通过判定；标识符、数字与否定词都不做归一化，也不对任何句子做白名单。

## Alternatives considered

**首次重复短语时立即取消。** 短暂重复阶段可能恢复为有用推理和真正的工具调用。延后中断保留这种机会，提前抑制则限制新增的已提交副本。

**丢弃签名或隐式退回 foreign 重放。** 元数据缺失不能证明提供方允许编辑。显式明文模式强制执行其更窄的表示；签名与未知路由保持保守。

**通过 idle 监听器续跑。** idle 是整个 agent 的状态，不是一次恢复的所有权。子代理管理器可能已经关闭准入，用户或父级也可能取消。循环内结算保留原有取消与 activation 所有者。

**引入另一种持久 partial-message 事件。** 现有读者已经理解不含已分派工具的中断前缀。复用该表示避免平行历史投影；扩展后的含义被明确记录，策略原因与轮次结果保持分离。

## Consequences

正常内容立即交付，因此检测前可能透传少量重复。精确证据无法证明语义有效性，也无法检测任意微变。仅过滤第一个推理索引，其他索引原样透传，且不会恢复先前丢弃的片段。本地抑制不减少提供方侧生成、计费或 SDK 缓冲。原生 spawn／fork activation 可以恢复；外部执行需要在自身运行时内配置策略。已有会话保持不变。

复现句子证据是启发式，并有实测下限：在其依据的录制会话中，106 条超过 2,000 字符的推理块有 7 条越过阈值，其中一条在此后约 4,000 字符内继续重复，随后自行恢复。

## Verification

包内 watch／policy 测试覆盖代表性短语重排、无分隔符周期、标识符／数字／否定词变化、分片划分、规范块闭合、工具保护、取消、清理失败、有限恢复和 fiber 卸载。原生 activation 测试覆盖 spawn／fork 的单次结算与原有谱系。本地 HTTP 协议测试覆盖显式明文投影和不透明元数据拒绝。人工构造的 headless 恢复场景运行正式 Loader 组合，将普通重试设为 always，且最终 Session 不存储原始重复载荷。

可见停滞测试覆盖录制到的近似重复形态、口头填充词之后的带序号进展、围栏脚手架、屏障释放、工具提交后的释放、每字符保留上限，以及不同分包下的一致性。延迟清理测试会挂起提供方迭代器的 return，并断言在没有持久结算时策略失败帧已可观测、清理不会再补一个 finish，以及清理完成后中断结算与其续跑提示按其顺序出现。会话测试断言实时窗口与重新打开的窗口得到同一个 Step 行、在守卫续跑期间不会把截断报告为停止，以及没有任何续跑接续的停止仍保持停止展示。
